# The hand-holdiness spectrum of AI agent autonomy

**Every AI agent operates within constraints — the question is whether those constraints are implicit or engineered.** From AutoGPT's recursive self-prompting loops to a PLC's deterministic scan cycle, the spectrum of agent autonomy is not a binary but a rich continuum of architectural choices trading off flexibility, reliability, efficiency, and safety. This report maps that continuum across twelve distinct architectural bands, identifies five critical gaps where no mature solution exists, and proposes novel architectures to fill them. The core finding: the industry is rapidly converging on a universal bounded-autonomy pattern — *propose within bounds, verify, escalate when uncertain* — but the tooling to implement this pattern coherently across the spectrum remains fragmented and immature.

---

## Twelve bands of the autonomy spectrum

The spectrum divides naturally into four zones — high autonomy, structured autonomy, constrained execution, and deterministic control — each containing two to four distinct architectural bands. Understanding the precise mechanisms of constraint at each level reveals why certain applications cluster at specific points.

**Band 1: Open-ended autonomous agents** represent the highest-autonomy tier. Systems like Manus (CodeAct over Claude 3.5 Sonnet + Qwen, acquired by Meta December 2025), OpenAI's ChatGPT Agent (merging Deep Research + Operator + CUA, July 2025), and Anthropic's Claude Code (terminal-native agent, GA May 2025) accept a high-level goal and autonomously decompose, plan, execute, and self-correct across multi-step tasks. They run in **sandboxed cloud VMs** with full tool access — shell, browser, code editor, file system. The ReAct pattern (Yao et al., ICLR 2023) underpins virtually all of them: interleaved Thought-Action-Observation loops where the LLM decides both *what* to reason about and *which tools* to invoke. Even these "fully autonomous" systems impose implicit constraints: token budgets, step limits, sandboxed environments, refusal training (OpenAI's CUA refuses **97%** of harmful requests), and human-approval gates for consequential actions. Performance on SWE-bench Verified has climbed from Devin's initial 13.86% to Claude 4.5 Opus breaking **80%**, but SWE-bench Pro (Scale AI, 2025) drops top models to ~23% when contamination is controlled.

**Band 2: Multi-agent orchestration frameworks** add role-based structure. CrewAI assigns agents explicit roles, goals, and backstories with hub-and-spoke communication. MetaGPT (Hong et al., ICLR 2024) encodes entire software development SOPs — PM → Architect → Engineer → QA — achieving **85.9% Pass@1** on HumanEval at ~$2 per project. Microsoft AutoGen v0.4 uses an event-driven actor model with dynamic group chat where an LLM selects the next speaker. The key architectural constraint here is *predefined agent topology*: who talks to whom, in what order, with what authority. This prevents the cascading hallucination problem that plagues single-agent systems — MetaGPT's structured outputs between roles significantly reduce error propagation.

**Band 3: Graph-based workflow orchestration** provides the developer with explicit control over execution flow while allowing LLM-driven decisions at each node. LangGraph (v1.0, 2025) models agents as nodes in **cyclic graphs** with centralized state, supporting loops, backtracking, and human-in-the-loop interrupts. Unlike LangChain's LCEL (DAG-only, no loops), LangGraph enables the supervisor-worker, swarm, and hierarchical patterns essential for production agents. LlamaIndex Workflows (v1.0) take an event-driven approach, while Haystack (deepset, v2.24) uses pipeline graphs with serializable YAML definitions. The constraint mechanism is the graph structure itself — developers explicitly define which transitions are possible, preventing unbounded agent behavior while preserving flexibility within each node.

**Band 4: Programmatic LM constraint** replaces prompting with programming. DSPy (Stanford, v2.6+) defines Signatures (input/output specs), Modules (composable LM strategies), and Optimizers that automatically tune prompts against metrics — achieving reliable behavior without brittle prompt engineering. Instructor (3M+ monthly downloads) enforces Pydantic model schemas via tool-use APIs with automatic retry on validation failure. Pydantic AI extends this to full agent runtimes with typed tools and structured outputs. The constraint here is *type-level*: the developer specifies what the LLM must produce (schema), and the framework guarantees compliance or retries.

**Band 5: Tool-use protocols** standardize the interface between agent and environment. The Model Context Protocol (MCP), now under the Linux Foundation's Agentic AI Foundation with **97M+ monthly SDK downloads** and **10,000+ active servers**, defines a client-server architecture over JSON-RPC 2.0 where tools expose typed schemas (JSON Schema), resources provide readable data, and prompts offer interaction templates. OpenAI, Anthropic, and Google all support function calling via JSON Schema definitions. MCP solves the M×N integration problem (M apps × N data sources) by collapsing it to M+N. The constraint is the *typed action space*: the agent can only invoke functions matching declared schemas, with the host responsible for execution and consent.

**Band 6: Constrained decoding and structured generation** operates at the token level. Outlines (dottxt) compiles JSON Schemas into **finite-state machines** that mask invalid tokens at each generation step — O(1) per-step overhead with precomputed vocabulary indices. Microsoft Guidance's llguidance engine achieves ~**50μs CPU time per token** for 128K tokenizers using on-the-fly mask computation. XGrammar (CMU, MLSys 2025) uses **pushdown automata** splitting the vocabulary into context-independent (~99%) and context-dependent (~1%) tokens, achieving **100x speedup** over prior CFG-constrained decoding. SGLang's RadixAttention provides up to **6.4x throughput** improvement via KV cache reuse. OpenAI's Structured Outputs (August 2024) and Anthropic's (November 2025) use constrained decoding internally to guarantee **100% schema compliance** — up from 35% with prompting alone.

**Band 7: Guardrails and safety layers** wrap agent behavior with validation. NVIDIA NeMo Guardrails uses the Colang language to define input/output/dialog/retrieval/execution rails with semantic similarity matching. Guardrails AI provides composable validators (toxicity, PII, regex, provenance) with configurable on-fail behaviors (reask, fix, refrain). Anthropic's Constitutional Classifiers (January 2025) reduce jailbreak success from **86% to 4.4%** with only 0.38% increase in false refusals and 23.7% inference overhead. These operate as **runtime wrappers** — model-agnostic, composable, but adding latency per layer.

**Band 8: Neuro-symbolic hybrids** combine LLM flexibility with symbolic guarantees. LLM+P (Liu et al., 2023) translates natural language to PDDL, invokes a classical planner (Fast Downward) for provably optimal plans, then translates back. SatLM (Ye et al., NeurIPS 2023) routes reasoning through Z3 SAT/SMT solvers, setting state-of-the-art on LSAT and BoardGameQA. AlphaProof (DeepMind, 2024) combines neural theorem proving with Lean 4 formal verification, solving **4 of 6 IMO 2024 problems**. The key insight from Kambhampati et al. (2024): "LLMs can't plan, but can help planning" — the LLM generates proposals, symbolic verifiers validate, and iterative correction loops produce sound results.

**Band 9: RLHF and preference alignment** shapes agent behavior at training time. The standard RLHF pipeline (Ouyang et al., 2022) trains a reward model on human preferences, then optimizes the policy via PPO with a KL divergence constraint against the reference model. DPO (Rafailov et al., 2023) eliminates the explicit reward model entirely through a closed-form loss on preferences. KTO (Ethayarajh et al., ICML 2024) goes further, requiring only binary desirable/undesirable signals — not paired comparisons — by modeling human cognitive biases from prospect theory. **Process reward models** that evaluate each reasoning step (not just final answers) have been critical for scaling reasoning capabilities in models like o1 and o3.

**Band 10: Behavior trees and planning architectures** from robotics and games provide hand-designed reactive control. Behavior trees tick top-down through Sequence (AND), Fallback (OR), Decorator, and Action nodes, returning SUCCESS/FAILURE/RUNNING. BehaviorTree.CPP is deeply integrated into ROS2's Nav2 stack for robot navigation. GOAP (Goal-Oriented Action Planning, first in F.E.A.R., 2005) uses A* search over precondition-effect action models. Utility AI (pioneered in The Sims) scores actions via response curves and selects the highest utility. These architectures are **fully deterministic** given their inputs and hand-authored — no learned components, no language models, complete predictability.

**Band 11: Task-specific RL** trains narrow policies through reward-driven trial-and-error. PPO, SAC, and TD3 dominate continuous robotics control, with SAC achieving **320.3 average reward** in bipedal walking versus PPO's 181.3. MuZero (DeepMind, 2019) learns an implicit dynamics model in latent space and plans via MCTS — matching AlphaZero on board games while mastering 57 Atari games without knowing the rules. Decision Transformer (Chen et al., NeurIPS 2021) recasts RL as sequence modeling, conditioning a GPT-style transformer on desired returns to generate optimal actions — bridging the RL and LLM architectural paradigms.

**Band 12: Deterministic industrial control** represents the lowest-autonomy extreme. PLCs execute ladder logic on **1-10ms deterministic scan cycles** — sense, execute, update — with IEC 61131-3 standardized programming. Model Predictive Control solves constrained optimization over a receding horizon at **50+ Hz** (Nav2's MPPI generates thousands of sample trajectories per cycle). TinyML models run keyword spotting on **16KB** Arm Cortex M3 microcontrollers consuming under 1 milliwatt. Every behavior is specified, verified, and bounded by hard real-time constraints.

## How safety-critical domains bound autonomy formally

The most mature bounded-autonomy frameworks come from aerospace, automotive, and defense — domains where failure costs lives. Their architectural patterns provide blueprints applicable across the spectrum.

**SAE J3016** defines six levels of driving automation anchored by two concepts: the **Operational Design Domain** (ODD), which formally specifies the conditions under which automation operates (Mercedes Drive Pilot: highway jams ≤40mph on mapped roads), and the **fallback mechanism**, which defines who handles situations outside the ODD. The critical boundary is Level 2 → Level 3: the shift from human-monitors-system to system-monitors-itself-and-requests-human-fallback. This graduated autonomy model directly maps to AI agents — every agent should have an explicit ODD and fallback policy.

**DO-178C** certifies airborne software through Design Assurance Levels (DAL A: failure rate ≤**10⁻⁹**, 71 verification objectives). Its DO-333 supplement explicitly permits formal methods (theorem proving, model checking, abstract interpretation) as alternatives to dynamic testing — making it the only major safety standard with a formal pathway for AI verification. The **Simplex Architecture** (Seto et al., 1998) implements runtime assurance: an unverified advanced controller operates normally while a verified baseline controller stands ready to take over if safety monitors detect impending violations. Extensions include the Black-Box Simplex Architecture (runtime verification instead of static), Distributed Simplex (multi-agent via Control Barrier Functions), and Neural Simplex (neural networks as both controllers).

**Mobileye's Responsibility-Sensitive Safety** (RSS) formalizes driving safety through five mathematical rules covering longitudinal distance, lateral distance, right-of-way, occlusion, and evasion. RSS operates as an **upper-level safety module constraining the output of underlying driving policies** — the planning system proposes, RSS restricts to a verified-safe envelope. This propose-constrain pattern appears everywhere safety matters: shield synthesis in safe RL constrains agent actions to those satisfying LTL specifications, CBFs enforce forward invariance of safe sets via quadratic programming at each timestep, and constrained MDPs augment standard optimization with cost constraints.

**Sheridan and Verplanck's ten levels of automation** (1978) remain the foundational taxonomy, ranging from "computer offers no assistance" to "computer ignores the human." Parasuraman et al. (2000) extended this with the insight that automation levels should be set *independently* for four stages: information acquisition, analysis, decision selection, and action implementation. A system might be highly automated for information gathering but require human approval for action — precisely the pattern emerging in modern AI agents with retrieval-augmented generation feeding human-approved tool calls.

## Five critical gaps in the spectrum

Despite the proliferation of frameworks, five regions of the spectrum lack mature solutions.

**Gap 1: Certifiable LLM agent frameworks.** No existing framework bridges the chasm between LLM-based agents and safety-critical certification standards like DO-178C or IEC 61508. LangGraph provides graph-based orchestration but offers no formal guarantees about agent behavior. Shield synthesis works for RL agents with finite action spaces but cannot handle the open-ended token space of LLMs. The ARc framework (2025) achieves **99.2% soundness** by autoformalizing policies into SMTLIB for inference-time verification, but this applies to individual LLM outputs rather than multi-step agent behavior. The missing piece is a framework that can provide probabilistic or formal guarantees about sequences of agent actions, not just individual generations.

**Gap 2: Dynamic autonomy allocation for LLM agents.** Adjustable autonomy is well-studied in robotics (Beer et al., 2014) and military systems, but no production framework implements graduated autonomy for LLM-based agents. Current systems are binary — either the agent acts autonomously or it pauses for human approval. There is no system that continuously adjusts the agent's action space based on real-time confidence calibration, environmental complexity, or accumulated trust. The Simplex-style "switch to a safer controller when confidence drops" pattern has not been adapted for LLM agents.

**Gap 3: Formally verified action-space constraints.** Constrained decoding guarantees syntactic validity of individual outputs (100% JSON schema compliance). Tool-use protocols constrain *which* functions can be called. But no framework constrains *sequences* of tool calls or *compositions* of actions with formal guarantees. An agent might make individually valid API calls that together produce an unsafe state. Shield synthesis from safe RL addresses this for finite action spaces, but the composition of typed tool calls into verified action sequences remains unsolved for LLM agents.

**Gap 4: Behavior-tree-LLM hybrids.** Behavior trees provide deterministic, hand-designed reactive control. LLM agents provide flexible, learned reasoning. No mature framework combines them — using behavior trees as the structural skeleton (defining the space of possible behaviors) while allowing LLMs to make decisions at leaf nodes or generate new subtrees dynamically. The closest analogue is GOAP + Utility AI hybrids in games, but these don't incorporate language models.

**Gap 5: Edge-cloud agent continuity.** Speculative decoding (SpecTr, SLED, EAGLE-2) enables edge models to propose and cloud models to verify at the token level. Split inference (Splitwise) partitions layers between edge and cloud. But no framework provides *agent-level* continuity — where a small edge model handles routine decisions within a behavior tree or state machine, seamlessly escalating to a cloud frontier model when it encounters novel situations requiring reasoning, and then returning distilled decisions back to the edge model for future similar situations. HERA (Hybrid Edge-cloud Resource Allocation) begins to address this for sub-task assignment, but the feedback loop for progressive edge model improvement is missing.

## Novel architectures for underserved regions

The following architectures address the identified gaps by combining proven patterns from different bands of the spectrum.

### Simplex-shielded LLM agents for safety-critical applications

The Simplex architecture's core insight — let an unverified high-performance controller operate while a verified baseline stands ready — translates directly to LLM agents. The architecture would consist of three components: an **advanced agent** (frontier LLM with tool access and reasoning capabilities), a **baseline agent** (small, fine-tuned model restricted to a verified-safe action subset, or a deterministic policy like a behavior tree), and a **runtime monitor** that evaluates each proposed action against formal safety specifications written in a temporal logic variant.

The monitor would use a combination of approaches: constrained decoding (ensuring individual outputs are structurally valid), a **learned safety classifier** (similar to Constitutional Classifiers, trained on the specific domain's safety violations), and a **formal action-sequence verifier** (checking that the proposed action, given the current state, does not lead to a state from which safety cannot be recovered within k steps — analogous to probabilistic shielding). When the monitor detects a potential safety violation, it switches to the baseline agent, which operates within a pre-certified action space. This is implementable today by combining LangGraph's state management with existing shield synthesis tools and deploying Constitutional Classifiers as the learned safety layer. The key research challenge is making the formal verification tractable for the combinatorial action spaces of tool-using agents — **compositional shield synthesis** (which has shown order-of-magnitude scalability improvements for multi-agent RL) offers a promising path by decomposing the action space into independently verifiable components.

### Graduated autonomy with typed action envelopes

This architecture introduces the concept of **typed action envelopes** — formally defined subsets of the full action space that expand or contract based on the agent's demonstrated reliability, the task's risk level, and real-time confidence scores. At Level 1, the agent can only select from a fixed menu of pre-approved actions (equivalent to a behavior tree's leaf nodes). At Level 2, it can compose approved actions into sequences validated by a planner. At Level 3, it can propose novel tool calls constrained by JSON Schema and validated by a lightweight verifier. At Level 4, it operates with full tool access but with output monitoring. At Level 5, it operates autonomously with only statistical auditing.

The system maintains a **trust accumulator** — a Bayesian model updated by comparing agent actions to verified outcomes. Trust accrues slowly (many successful actions raise the level) and erodes quickly (a single safety violation drops the level). This mirrors the asymmetric property of KTO's prospect-theory-inspired loss function: losses weigh more heavily than gains. The action envelope at each level is defined using JSON Schema extensions that specify not just parameter types but **pre/post-conditions and invariants** — essentially PDDL-style action definitions embedded in a tool-use protocol. MCP's existing tool schema could be extended with `preconditions`, `effects`, and `safety_invariants` fields, enabling automatic envelope verification without changing the underlying protocol.

### Behavior-tree-rooted LLM agents

This hybrid places a behavior tree at the architectural root, providing deterministic structure, while using LLM calls at specific decision points for flexibility. The behavior tree defines the high-level task structure — sequences of phases, fallback recovery behaviors, condition checks — exactly as in ROS2's Nav2 stack. But instead of hand-coding every action node, certain leaf nodes are **LLM-backed decision points** that invoke a language model with a constrained prompt and structured output schema.

The architecture supports three types of LLM integration: **leaf substitution** (an action node calls an LLM to decide how to execute a specific step, constrained by Pydantic models and guardrails), **subtree generation** (a decorator node calls an LLM to generate a new subtree in the behavior tree's XML DSL, which is then parsed and validated before insertion), and **condition evaluation** (a condition node calls an LLM to assess whether a complex, linguistically-described condition holds). The behavior tree provides guaranteed reactivity (it re-evaluates conditions every tick), bounded execution time (each LLM call has a timeout, falling back to a default branch), and compositional modularity. BehaviorTree.CPP's existing XML DSL and plugin architecture make this implementable by creating an `LLMActionNode` plugin that wraps calls to any MCP-compatible tool server.

### Progressive edge-cloud agent distillation

This architecture maintains two models — a small edge model (1-3B parameters, quantized to INT4, running on NVIDIA Jetson or mobile hardware) and a cloud frontier model — connected by a continuous learning loop. The edge model operates within a behavior tree or state machine handling routine decisions at **millisecond latency**. When the edge model's confidence (calibrated via temperature scaling) drops below a threshold, it packages the current state and context and sends it to the cloud model for resolution. The cloud model's decision is returned to the edge for execution, but critically, it is also added to a **distillation buffer** — a growing dataset of (context, decision) pairs from the cloud model's superior reasoning.

Periodically (hourly, daily, or triggered by buffer size), the edge model is fine-tuned using QLoRA on the distillation buffer, progressively expanding the set of situations it can handle locally. This mirrors the LoRA-Gen approach (2025) where cloud models generate LoRA parameters for edge models, but adds the continuous feedback loop. The escalation mechanism directly implements the Simplex pattern: edge model as advanced controller (fast, approximate), cloud model as the authority (slow, accurate), with confidence-calibrated switching. Over time, the edge model's confidence boundary expands as it absorbs the cloud model's knowledge, reducing cloud dependency. The system tracks escalation frequency by situation type, providing an automatic curriculum — the edge model is trained primarily on the situations it finds hardest, maximizing the value of each distillation cycle.

### Action-sequence verification via compositional shields

This architecture addresses Gap 3 — verifying sequences of tool calls, not just individual outputs. It decomposes the agent's action space into **typed action categories** (read operations, write operations, financial transactions, external communications, system modifications), each with an independently verifiable safety specification written in LTL. A compositional shield monitors the agent's action history as a trace over these categories and blocks any action that would violate a safety property of the composition.

For example, the specification `G(write_database → X(verify_backup))` ("globally, every database write must be immediately followed by backup verification") or `G(¬(external_email ∧ ¬approved_content))` ("never send an external email with unapproved content") can be monitored in real-time with minimal overhead. The composition theorem from shield synthesis research guarantees that if each component shield is correct and the decomposition is admissible, the composed shield is correct. This makes the approach **scalable**: adding a new tool requires only defining its category and adding category-level safety properties, not re-verifying the entire action space. Implementation would layer this as a middleware between the agent's action selection (in LangGraph or similar) and tool execution (via MCP), intercepting each tool call, updating the trace, and querying the compositional shield before permitting execution.

## Where the spectrum is heading

Three convergence trends are reshaping the autonomy landscape. First, **MCP as universal action interface**: with 97M+ monthly SDK downloads and adoption by every major AI lab, MCP is becoming the typed action layer that makes tool-constrained autonomy the default rather than the exception. The November 2025 additions — tool search across thousands of servers, programmatic tool calling where the LLM writes code to orchestrate tools — push MCP from simple function calling toward a genuine agent operating system.

Second, **constrained decoding is becoming invisible infrastructure**. XGrammar's integration as the default engine in vLLM and SGLang means that structured output is no longer a special mode — it's the baseline. OpenAI and Anthropic both ship constrained decoding in their APIs. The performance overhead debate is effectively over: guidance achieves 50μs per token, XGrammar achieves near-zero overhead. The question is no longer *whether* to constrain outputs but *at what semantic level* — tokens, schemas, action sequences, or behavioral traces.

Third, **the Simplex pattern is emerging as the universal safety architecture** across the spectrum. Whether it's a baseline controller for a drone, a safety classifier for an LLM, or a verified edge model backing a cloud agent, the propose-verify-fallback pattern appears independently in every domain addressing safety. The missing piece is a unified framework that implements this pattern with pluggable components — any advanced controller (LLM, RL policy, MPC), any monitor (formal verifier, learned classifier, rule engine), and any baseline (deterministic policy, constrained model, human escalation).

The ultimate architecture is not a single point on the spectrum but a **stack** that combines multiple bands: constrained decoding at the token level, typed tool schemas at the action level, guardrails at the semantic level, behavior-tree structure at the task level, and formal safety envelopes at the system level. Each layer adds a different kind of constraint, and the combination provides defense in depth. No single framework delivers this full stack today — but the components exist, and the interfaces (MCP for tools, JSON Schema for structure, LTL for safety) are converging. The engineering challenge of the next two years is composition: making these layers work together with acceptable latency, clear failure semantics, and principled autonomy allocation.

## Conclusion

The hand-holdiness spectrum is not linear but **compositional** — production systems combine multiple constraint mechanisms simultaneously. The most important architectural insight is that autonomy and constraint are not opposed but complementary: a well-constrained agent can be trusted with *more* autonomy precisely because its failure modes are bounded. The five identified gaps — certifiable LLM agents, dynamic autonomy allocation, action-sequence verification, BT-LLM hybrids, and edge-cloud continuity — all share a common thread: they require bridging the formal methods tradition (which provides guarantees) with the LLM agent tradition (which provides flexibility). The proposed architectures address this by applying proven patterns (Simplex, compositional shielding, graduated autonomy levels, progressive distillation) to the new context of language-model-powered agents. The spectrum is not a menu to choose from but a toolkit to compose — and the winners will be the frameworks that make that composition natural, efficient, and verifiable.
